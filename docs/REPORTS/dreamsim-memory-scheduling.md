# Memory and scheduling

Gradient checkpointing: measured, off by default, trap documented (`backbones.py:304-310`, `443-461`). HF checkpointing only engages in `train()` mode, so the frozen tower must not be pinned to eval: "eval-mode = no checkpointing, 1214 MiB; train-mode = checkpointed, 750 MiB". Cost "~30% compute … 0.4 GiB/triplet at the 544 budget" (`train.py:278-281`); `use_reentrant=False` keeps grads reaching adapters (`backbones.py:405-408`). → Relevant to your 22 GB batch-64, but it HURTS img/s at 359 ms; use it only to fit a memory-bound config
VRAM ladder, same tower (`MEMORY.md:629-632`, DINOv3-B @288², ckpt on, all-six adapters): b12p 4316 / b16p 5639 / b20p 6959 MiB; "b32p k8 (288 img/step) and b28p k8 OOM at 288; b24p k8 (216 img) fits". Their lever at the wall was micro-batching with grad accumulation (`train_rotasim.py:551-557`: loss is a SUM over slots, forward+backward per group and one `opt.step()` … "MATHEMATICALLY IDENTICAL to one big batch — but autograd only holds ONE group's activations"), not checkpointing. → High: batch-64-equivalent optimisation at batch-32 memory, no compute tax
`anti_creep`: `empty_cache()` only when reserved−peak > 2 GiB, every 25 steps (`train.py:1266-1276`); `cuda_settle()` does `synchronize()`+`gc`, deliberately not `empty_cache()` (`1258-1264`). On WDDM the cache "releases on the driver side outside torch's accounting and the ensuing host-commit churn wedged the input pipeline for the rest of the run" (`718-722`). → High (Windows-only): delete any in-loop `empty_cache()`
No `set_per_process_memory_fraction`, no in-code allocator tweaks — A/B'd externally, all rejected (`docs/startupflags-costs.md:6-9`). → Don't spend time
No CUDA graphs, no dual-stream prefetch, no async checkpointing. `save_checkpoint` is a blocking `torch.save` + blocking `shutil.copy2` of the whole file each boundary (`train.py:1699-1712`) — cheap at ~5 MB (`model.py:635-637`: "~5 MB instead of ~1 GB"), but not with your 19.2M head + optimizer state. → Gap on your side.
Logging bounded: one JSON line per `log_every=10` (`train.py:1642-1690`) with `host_mem_sample()` (ctypes `GlobalMemoryStatusEx`, `771-803`) and `adapter_health()` (`@torch.no_grad()` walk, `806-812`). → `host_commit_pct` is a cheap early wedge detector
